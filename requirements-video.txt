# --- GPU para los modelos de Roboflow (jugadores/cancha), sin pycuda -----
# Dos intentos fallidos antes de encontrar la solución, para no repetir el
# camino:
#   1. `inference-gpu` -> arrastra `pycuda`, que necesita compilar contra el
#      toolkit CUDA completo (nvcc) y falla al construir el wheel.
#   2. `inference` normal + reemplazar onnxruntime por onnxruntime-gpu a mano
#      -> onnxruntime SÍ carga CUDA, pero la librería interna de Roboflow
#      (`inference_models`) exige `pycuda` en tiempo de ejecución para el
#      camino GPU del backend ONNX ("Running model with ONNX backend on GPU
#      requires pycuda installation") -- mismo bloqueo que el punto 1.
#
# Solución que SÍ funciona (Windows): DirectML, la API de aceleración nativa
# de Windows -- funciona con cualquier GPU (NVIDIA/AMD/Intel) sin necesitar
# el toolkit de CUDA ni pycuda. `inference` nunca la pide por su cuenta, así
# que hay que instalar el wheel de onnxruntime con soporte DirectML Y pedirla
# explícitamente por variable de entorno (ver .env.example):
#
#   pip uninstall onnxruntime
#   pip install onnxruntime-directml
#   # en .env: ONNXRUNTIME_EXECUTION_PROVIDERS=DmlExecutionProvider,CPUExecutionProvider
#
# Medido: ~2.6x más rápido que CPU pura en la GTX 1050 Ti.
onnxruntime-directml
